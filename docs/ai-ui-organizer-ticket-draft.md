# AI 整理 UI 实现任务拆分草案

状态：待确认拆分及工单位置，未发布。设计规格中未决选项保持未决。

## 01：手动抽取同结构组件并生成真实嵌套实例

依赖：无。

交付：用户选择一组同结构组件，输入名称，预览并应用固定抽取方案，生成当前界面 Common 中的公共 Prefab 和对应实例。

- 最小操作入口、方案校验、生成及重新加载验证形成闭环，不依赖 AI。
- 保留不同图片、文字、颜色、布局和排序；原位置成为真实嵌套实例。
- 无效成员、交叉引用及输出冲突在写入前报告。
- 未执行抽取的旧生成流程不变；取消预览不修改资产。

## 02：同结构抽取规则保存与重复生成

依赖：01。

交付：关闭并重新打开项目后，重新生成仍使用原组件及实例映射。

- 同样输入重复生成不增加公共资产或重复实例。
- 公共资产身份和外部引用保持有效。
- 重名、改名和排序变化不靠猜测匹配；无法确定身份时报告冲突。

## 03：结构差异组件的公共部分和状态抽取

依赖：02。

交付：普通奖励和特殊多奖励组件共用一个包含公共部分及状态分组的组件，各实例保留默认形态。

- 预览列出有序公共成员、状态成员及实例对应状态。
- 应用后各实例保持原画面，重复生成后状态映射不丢失。
- 实现前确认运行时状态切换组件是否属于首版；保存默认状态本身不依赖运行时组件。

## 04：重新生成时保留手工修改与冲突处理

依赖：02。

交付：比较原生成结果、手工修改与新 PSD 结果，保留脚本、事件和实例覆盖，并展示冲突。

- 用真实保存资产验证脚本引用、事件目标及属性覆盖。
- 同一属性两侧变化、成员删除和身份丢失有具体冲突说明。
- 无冲突源变化正常更新，冲突内容不被静默覆盖。
- 实现前确认整体生成还是部分生成的事务边界，并测试写入失败恢复。
- 与03同时开发时，公共组件协议变更需协调；结构差异冲突在07集成验证。

## 05：统一 AI 整理入口完成类型与层级整理

依赖：无；交互方式确认后可开始。

交付：通过选定的统一界面启动现有 CLI 类型/层级分析，查看进度、预览变更并应用。

- 复用现有 provider 和结果校验，避免引入第二套任务运行器。
- 过期快照不能应用；失败和取消不改变编辑树。
- 如采用 Unity 窗口方案，终端为可选日志入口，现有应用能力整合进预览。
- 此任务不需要等待公共组件抽取核心，先完成既有识别能力的新交互闭环。

## 06：skill 驱动的重复组件分析与方案修订

依赖：03、05。

交付：从统一整理入口分析重复组件，预览公共成员及差异，修改名称或排除实例后应用生成。

- skill 随 PSD2UIForm 发布，不依赖 PSDLayoutTool2 或个人技能目录。
- 协议版本、真实节点 ID、指纹和成员映射统一校验。
- 分组后出现的抽取目标必须符合预览清单，不自动扩大范围。
- 受控 CLI 结果可端到端重复验证，真实 CLI 调用作为接入验收。

## 07：完整生成更新与兼容验收

依赖：04、06。

交付：解析编辑树、AI 整理、公共组件生成、手工修改、PSD 更新与再次生成的完整链路通过验收。

- 验证同结构和结构差异实例的更新、覆盖和冲突。
- 验证 ref、refp、九宫格及 Slider 图片角色继续有效。
- 验证分析取消、应用失败、生成失败的最终保存状态。
- 签到资产只作为验收样例，另用不同命名和结构的样例证明规则通用。
