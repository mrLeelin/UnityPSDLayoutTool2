# PSD2UIForm AI 整理与公共组件抽取规格

状态：部分实现；01—03、05—06 已交付，04 的源更新合并和 07 的完整更新验收尚未完成。

## Problem Statement

PSD2UIForm 能识别 UI 类型、修正编辑树、导出公共 Prefab 并通过 refp 引用，但缺少从重复 UI 中提取公共结构、替换为嵌套实例并保留实例差异的完整能力。用户希望从首次 PSD 解析得到的编辑树进入统一的 AI 整理流程，获得按功能组织、重复部分可维护的 UI。

现有外部 CLI 分析和独立应用按钮不能充分展示抽取边界、各实例差异和将生成的公共资产。只修改最终 Prefab 也不足以保证下次生成仍保留整理结果。

## Solution

复用现有 CLI 能力，使用插件随附的整理 skill 分析编辑树及预览，形成统一、可校验的整理方案。方案覆盖类型识别、功能分组和公共组件抽取。用户审阅后，应用编辑树调整并保存抽取规则；生成 UIForm 时创建真正的公共 Prefab 与嵌套实例。

已确认首版包含结构不同的重复组件，通过公共部分与状态分组保留差异；公共组件默认属于当前界面；再次生成保留新增脚本、事件绑定和手工覆盖，并报告与 PSD 更新的冲突。

统一窗口、后台 CLI 和可选终端日志已经用户确认并实现。当前发布到新目录，已有输出的源更新合并及运行时状态切换仍未实现。

## User Stories

1. 作为 UI 制作者，我希望从解析后的编辑树启动整理，以便不必先手动整理最终 Prefab。
2. 作为 UI 制作者，我希望统一查看控件类型、归属和组件抽取建议，以便理解完整整理结果。
3. 作为 UI 制作者，我希望只选择需要的整理项目，以便保留已经正确的部分。
4. 作为 UI 制作者，我希望 AI 使用图层快照和预览分析，以便建议对应真实节点。
5. 作为 UI 制作者，我希望补充整理要求，以便表达不能仅从画面确定的功能边界。
6. 作为 UI 制作者，我希望将背景、图标和文字归到正确控件，以便功能层级清晰。
7. 作为 UI 制作者，我希望识别重复组件，以便共用可维护的公共结构。
8. 作为 UI 制作者，我希望提前看到组件的成员与所有实例，以便避免错误抽取。
9. 作为 UI 制作者，我希望修改公共组件名称并排除不适合的实例，以便纠正 AI 建议。
10. 作为 UI 制作者，我希望各实例保留自己的图片、文字、颜色和布局，以便抽取不改变画面。
11. 作为 UI 制作者，我希望结构不同的重复项也能参与抽取，以便处理普通日期和特殊日期奖励。
12. 作为 UI 制作者，我希望预览公共部分、状态成员和每个实例的默认状态，以便知道差异如何保存。
13. 作为 UI 制作者，我希望公共组件默认保存在当前界面的 Common 目录，以便明确组件的使用范围。
14. 作为 UI 制作者，我希望原位置替换为真实嵌套 Prefab 实例，以便公共结构修改能够传播。
15. 作为 UI 制作者，我希望已有 ref、refp 和九宫格设置继续正确工作，以便新增抽取能力不破坏现有制作流程。
16. 作为 UI 制作者，我希望整理规则被保存，以便重新打开项目或再次生成时继续使用。
17. 作为 UI 制作者，我希望再次生成保持公共资产身份和实例引用，以便其他引用不因重建而失效。
18. 作为 UI 开发者，我希望生成后新增的脚本与事件绑定被保留，以便不丢失业务集成。
19. 作为 UI 制作者，我希望重新生成时保留手工覆盖，并在与 PSD 更新冲突时得到具体提示，以便做出选择。
20. 作为 UI 制作者，我希望过期方案或无法匹配的节点被指出，以便不会将结果应用到错误对象。
21. 作为 UI 制作者，我希望失败或取消分析时现有资产不变，以便可以重新分析。
22. 作为插件使用者，我希望整理 skill 随插件提供，以便不依赖另一个插件或个人技能目录。
23. 作为插件维护者，我希望用固定方案验证生成行为，以便 AI 输出变化不影响核心回归测试的确定性。

## Implementation Decisions

### 已确认的产品边界

- 公共组件抽取是独立于图片引用和公共 Prefab 引用的操作，不以批量添加 refp 标记代替实例差异保存。
- 首版覆盖相同结构及具有结构差异的重复组件。
- 公共组件默认输出到当前界面旁的 Common 目录。全局共享需明确操作。
- 重新生成保护新增脚本、事件绑定及手工覆盖，冲突不得静默覆盖。

### 拟采用的技术设计

以下为待实现规格中的设计提案，不代表访谈第二轮已被确认。

- 复用 AI 任务编排、CLI provider、任务结果存储及现有 UI 类型识别能力，扩展统一方案协议。
- 整理 skill 负责分析和方案输出；确定性执行器负责验证、层级修改、资产生成和实例替换。
- 插件自带整理 skill 与协议说明。沿用旧整理 skill 的节点身份、布局保护和组件分析经验，但适配编辑树到最终 UI 的生成流程。
- 输入包括来源身份、当前快照指纹、真实节点 ID、类型与关系、预览信息和现有引用。AI 不得凭名称猜测节点 ID。
- 方案包括协议版本、输入指纹、类型与层级变更、公共组件定义、成员映射、实例差异、状态定义、默认状态与输出目标。
- 规则持久化并与源文档、组件和实例的稳定身份关联。不能仅依赖当前名称或路径恢复规则；身份匹配失败应报告冲突。
- 在候选状态中验证方案，检验未知节点、循环关系、重叠抽取、嵌套引用、外部绑定、布局边界及资产路径冲突。验证失败不得写入正式资产。
- 生成时保留位置、尺寸、锚点、排序、可见状态和序列化引用。共有资源的修改不得被误当成某一个实例的独立差异。
- 公共结构、状态成员和实例覆盖的适用范围必须显式记录，不能把所有差异压成单一模板。
- 重新生成需要比较原生成基线、当前手工修改及新的生成结果，识别冲突。稳定身份与三方合并的具体实现须验证现有生成元数据能否承载。
- 应用入口只接收经过验证的方案；UI 预览与实际执行必须使用同一份方案。
- 所有规则对 PSD 文档通用，不按某个签到示例的节点名编写特例。

### 尚待确认

- Q4：建议仅保存默认样式，运行时状态切换由项目业务代码负责；是否需要首版提供切换组件未定。
- Q5：建议先解决全部冲突再执行整体生成；是否允许无冲突部分先生成未定。
- Q6：建议使用 Unity 内统一整理窗口与后台 CLI；是否继续以外部终端为主未定。
- 图片、文字、布局及已有引用发生结构性变动时，实例覆盖的完整支持范围需要在实现前形成可测试清单。

## Testing Decisions

### 建议的主测试边界

从真实编辑树与固定整理方案调用生产方案应用、UI 生成及再次生成入口；验证保存后重新加载的 Prefab 资产与嵌套实例。优先使用现有生成入口，不以私有方法或模型字段是否赋值代替行为验证。此测试边界待用户确认。

AI 推理不作为回归测试通过的必要条件。协议接入另用受控 CLI 结果验证；最终补一次真实 CLI 到生成结果的人工可见验收。

### 验收案例

1. 相同结构的重复项抽取为一个普通公共 Prefab，各实例具有真实源资产连接。
2. 实例的图片、文字、颜色、布局和可见状态在抽取前后相同。
3. 普通单奖励与特殊多奖励组件共存，公共部分和状态成员映射正确。
4. 同一方案再次生成不重复创建资产或实例，公共资产 GUID 和既有绑定保持有效。
5. 修改源 PSD 后，非冲突变化正确更新，手工新增脚本、事件引用和覆盖保留。
6. 同一属性双方修改、源成员删除、身份匹配失败分别产生可理解的冲突，受冲突影响的手工内容不被静默覆盖。
7. 旧快照、无效 ID、循环引用、重叠成员、非法输出及不支持的协议版本被拒绝。
8. 模拟分析失败和取消时，正式资产不发生变化；应用/生成失败的恢复行为按最终确认的事务边界验收。
9. 原有 ref 图片复用、refp 嵌套、引用源九宫格与 Slider 图片角色不退化。
10. 整理分组后才出现的重复组件，最终抽取必须匹配用户预览的成员与实例清单。
11. 中文节点名、重名节点及重新排序不会被当作同一对象或造成错误匹配。
12. 插件随附 skill 能在不安装 PSDLayoutTool2 的条件下被加载并完成协议调用。

### 可参考的既有测试

- PSDLayoutTool2 的层级整理执行测试：组件抽取、状态结构、预检查和嵌套保护。
- PSDLayoutTool2 的增量 Prefab 合并测试：生成更新、资产身份和引用保护。
- PSD2UIForm 的现有生成入口及现场九宫格验证：作为回归路径参考，不能以编译通过代替资产和画面验收。

## Out of Scope

- 修改 Photoshop 导出脚本。
- 替换现有 CLI provider 或引入独立网页应用。
- 自动把界面局部组件提升为全局共享组件。
- 对指定签到资产进行一次性整理，代替通用能力实现。
- 未经验证的 AI 自由执行代码或直接编辑正式 Prefab。

运行时状态切换组件尚待确认，暂不列为已确定的范围内或范围外。
